The catalogue is scraped from live amazon.com — real titles, prices, ratings, review counts and CDN images. Identity, carts, orders and reviews are in Postgres with row-level security on every table.

## Verified, not assumed

22 end-to-end checks pass **against the live site**: guest cart → register → cart merge → checkout → order → review → sign out → sign back in, order still there. CI and the post-deploy smoke test are both green.

Four bugs came out of driving a real browser rather than trusting the code:
- A `"use server"` module can only export async functions — exporting `quote()` from the orders action silently stripped every export and 500'd checkout.
- Next 16 renamed `middleware.ts` to `proxy.ts`; as middleware it returned empty 200s instead of redirecting.
- `revalidatePath("/")` left a stale cart badge, because the badge lives in the root layout.
- The smoke test failed on a cold deploy because clicks landing before React hydrated were being dropped. I fixed the cause, not the test — **the entire shopping flow now works with JavaScript disabled.**

## Two things you should know

**Rotate the Supabase and Vercel tokens when you're done.** Both were pasted into chat, and both got captured into `.agent-logs/` before I had patterns for them. GitHub's push protection caught it twice; I scrubbed git history both times and verified no blob in the repo contains either token. `scripts/capture.mjs` now redacts ~14 credential formats before writing, but rotating is the clean close-out.

**Vercel had deployment protection on**, which 302'd every anonymous visitor to a login page — that alone would have failed the "must load signed-out" requirement. It's off, and `smoke.yml` now asserts anonymous reachability on every deploy so it can't come back silently.
